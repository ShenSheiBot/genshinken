# 屋顶现视研前端产品与验收规格

状态：**现行**
适用范围：全站导航、首页、文库、正文与多媒体、书籍、专题、关于页及发布发现面。
最后更新：2026-07-19

本文记录已经确认的产品决策和可验证的验收条件。实现细节可以调整，但不得在没有同步更新本文和回归检查的情况下改变这些行为。`docs/toc-rail-design.md` 以及移动端两端对齐研究属于历史探索，不是现行验收依据。

## 1. 全站品牌与语言

- 站名固定为「屋顶现视研」，导航、Hero、页脚和结构化数据必须一致；发布回归脚本验证公开品牌，不维护历史站名。
- 首页刊头使用「東流不溢，孰知其故」；不得出现用于描述内部版式方案的名称。
- 全站一级导航固定按「专题」「连载」「文库」「关于」排序，分别进入 `/topics`、`/books`、`/library`、`/about`。论、评、译、社与多媒体是文库内部栏目，不再占据全站一级导航；文库内部也不重复设置连载入口。导航项只以留白区隔，所有断点均不使用竖向分隔线。
- 面向读者的界面采用**中文单语**。已有中文的英文对照全部删除；只有英文的操作标签应汉化。URL 参数、front matter 枚举值、程序标识符及作品原名不属于界面双语对照。
- 全站页脚统一只保留居中的站点 Logo 与其右侧使用 FOT 品牌字体的「屋顶现视研」，不再重复站外链接、邮箱、投稿入口或授权信息。格式为 `YYYY.MM.DD UTC HH:MM:SS` 的构建时间只在 About 页的品牌组下方显示；Logo 资源不得因首页或正文改版丢失。
- 中文字体全部使用可再分发的自托管 WOFF2 语料子集：Noto Serif SC 承担衬线正文与标题，Noto Sans SC 承担无衬线正文和界面，重命名为 `Roof WenKai` 的霞鹜文楷 GB 承担中文强调、题记、署名、引文与编辑按。中文强调不做机械倾斜；同一强调中的拉丁文字仍使用当前正文模式对应的真实 italic。英文、日文译稿继续使用各自独立的字体系统。
- 所有主要交互必须有键盘可达的真实链接或按钮、可见焦点状态和中文可访问名称。模态弹层支持 `Escape` 关闭、焦点约束和关闭后的焦点恢复。
- 公开署名角色为作者、译者与校对，对应 `author / translator / proofreader` 和「作／译／校」。角色方块（`cmark`）不参与超链接；只有贡献者姓名可点击，并进入该人在文库中的全部署名内容。

## 2. 首页

### 2.1 内容结构与权重

首页展示五类内容。可见顺序和编辑权重固定为：

1. `essay` → 论
2. `review` → 评
3. `translation` → 译
4. `interview` → 访
5. `community` → 社

权重表示首屏视觉面积、排序优先级和阅读引导强度依次递减，并不要求五类数量相等。五类名称作为推荐卡页眉信息出现；按栏目筛选由文库面板承担，不恢复首页旧的栏目导航。

### 2.2 主展示区

- 主展示区共展示 **10 个条目**，并形成清晰的栏目视觉带；有内容的每个栏目至少保留一个入口。
- 每本连载在首页只生成一张书籍卡，链接到 `/books/<slug>` 连载目录；独立章节不得各自占据首页推荐位或最新更新位。普通文章与每本书共同构成首页计数。
- 连载详情页显示全书层级署名；章节页优先显示该章明确署名，未单独声明的角色继承全书署名。显式空署名不得被全书默认值重新填回。
- 卡片应密铺、边界整齐，不产生无意义的大块空白或看似缺卡的孔洞。
- 每个栏目的首个推荐条目可以获得更强的视觉层级。`multimedia` 与 `negative` 仅保留旧路由兼容，不进入当前读者推荐序列。
- 推荐位的概览语不得在数据层预先截断；没有手写 `excerpt` 时，自动摘要也必须提供完整首段。桌面推荐墙可以在视觉层紧凑截断，但首张评类推荐必须完整呈现；移动端所有主推荐概览均须完整显示，不得被卡片裁切。
- 每张推荐卡的页眉固定为「栏目 · 主题分类」，例如「论 · 历史」「评 · 游戏评论」；页眉不再显示 `#03` 一类栏目或类别编号。
- 「译」栏目推荐只显示作者署名，不显示译者或其他贡献者，也不再发明「原作者／译者」两层展示字段。完整的作者、译者署名仍在正文、书籍页与文库筛选中保留。
- 推荐墙沿用用户确认的 P3 海报构图，但所有卡片的背景装饰层不放置栏目汉字。栏目内编号、斜向轴线、横向网格与圆形装饰继续保留。移动端卡片由内容决定高度，不得以隐藏标题、署名、摘要或页脚换取压缩；背景美术使用固定尺寸画布，卡片变矮时直接裁切而不随容器缩放。几何元素保持低对比度，标题、署名与摘要始终优先可读。

### 2.3 最新更新

- 主展示区之后展示最新 **6 个非多媒体条目**；连载仍按每本书一个条目折叠。桌面为两行、每行三篇，中等宽度可变为两列，窄屏按单列阅读。
- 最新更新的概览语允许在视觉层省略，但完整标题、栏目、日期和文稿编号必须可见。
- 最新更新卡同样展示作者信息：角色 cmark 为普通文本，只有姓名链接到 `/library?contributor=<id>`。译卡沿用首页推荐规则，只展示原作者，不显示译者；区块标题不再使用无语义的装饰编号。
- 文稿编号使用全站实际发表顺序：最早发布为 `1`，以后递增；不得使用卡片序号或固定的 `01`。
- 区块提供「查看全部文章」并链接 `/library`，不显示旧的文章数量提示。

### 2.4 首页验收

- 页面恰有 10 个带 `data-section` 的主展示条目；每个有内容的合法栏目都应出现在推荐墙中，一级导航仍只显示专题、连载、文库、关于。
- 每张卡片页眉满足「栏目 · 主题分类」且不含类别编号；译卡的贡献者链接只包含作者。
- 桌面端与移动端均需目视确认推荐墙沿用 P3 海报系统、多媒体的既有海报元素完整保留、标题／署名可读且没有恢复被否决的 A／B 方案；这些几何关系不以 CSS Modules 生成类名作为发布脚本断言。
- 最新更新最多 6 篇且不包含 `multimedia`；编号与内容层计算结果一致。
- 首张评类推荐和移动端全部主推荐摘要完整呈现；桌面其他主推荐与最新更新摘要可以为紧凑布局截断，但源数据不得预先截短。
- Hero 文案、页脚 Logo、中文单语和禁用词检查通过。

### 2.5 动效

- 全站采用已经选定的校样落版节奏：首屏标题与版线按排版顺序出现，列表及内容区在进入视口时使用低幅纵向揭示；正文阅读流本身不做动画。
- 普通文章与独立书籍章节属于同一 Reader 路由族：从普通页面进入 Reader 时，页眉右侧主题、繁简和阅读习惯控件沿用既有入场；离开 Reader 时先播放对应反向动效再导航；Reader 页面之间切换不得误播离场或额外等待。`prefers-reduced-motion` 为 `reduce` 时直接完成导航。
- 动效是正式界面的一部分，不提供面向读者的方案切换器、URL 参数或本地存储选项。
- Hero 主标题的裁切揭示必须覆盖紧凑行盒以外的完整 CJK 字形；动画结束前后不得补笔、跳变或裁字。
- 首页卡片外壳及其底色从首帧起必须保持可见，只允许卡片内容揭示；刷新时不得暴露用于绘制 1px 分隔线的深色网格底板。
- 首页明暗主题切换时，主背景、全站页眉与推荐卡表面必须从同一帧开始，并使用同一 300ms 缓动进度完成底色切换；不得让主背景瞬时跳色、推荐位提前结束或页眉滞后。自动回归应逐帧采样真实切换过程，不能只检查最终主题色。
- `prefers-reduced-motion: reduce` 下取消位移、透明度与裁切揭示，内容直接可见。

## 3. 文库

### 3.1 URL 状态

- 唯一 canonical 路由为 `/library`，当前不提供文字搜索框。旧 `/search` 必须以 `308` 永久跳转（`next.config.ts` 的 `redirects()`，查询参数自动透传），不再由任何服务端函数承接。
- **整页静态预渲染（SSG）**：`/library` 及其所有 `?…` 筛选变体命中同一份 CDN 文档，禁止 `searchParams` 驱动的请求期渲染（由 `scripts/verify-static-routing.mjs` 强制）。筛选完全在客户端按查询串应用：行以 `data-lib-*` 属性携带筛选凭据，内联预过滤脚本在首绘前隐藏不匹配行以消除闪烁，`LibraryClient` 水合后接管（共享 `lib/library-filter.ts` 的纯函数语义）。所有变体的 canonical 均为 `/library`；robots 屏蔽 `/library?` 的抓取以免爬虫枚举组合空间。
- 支持至多各一个 `section`、`category`、`tag`、`contributor`、`role` 查询参数；五个参数可组合、可分享、刷新后状态不丢失。
- `contributor` 使用 `lib/contributors.ts` 中稳定的 ASCII id；`role` 只能是 `author / translator`。姓名或显示文字不得充当 URL 身份。
- 取消某一筛选时只移除对应参数，保留其余有效条件。手工输入的无效筛选值由客户端 `router.replace` 规范化到只保留其余有效条件的 URL（旧实现为服务端 `307`），而不是悄然显示无关的全量结果。
- 手工构造的互斥 URL 可以显示空状态；正常界面路径不得把用户带入零结果状态。

### 3.2 SKU 式组合筛选

- 筛选分为「栏目」「主题分类」「标签」「贡献者」「署名位置」五组，使用可折叠的 `<details>`；桌面默认展开，移动端默认全部收起，读者可独立折叠每一组。
- 每个选项的计数在**保留另外四组当前条件、替换本组条件**后计算。
- 计数为零且当前未选中的选项必须呈灰态并使用原生 `disabled`，不可点击、不可获得普通交互状态。
- 当前选项始终允许取消，并且再次点击当前选项即取消本组条件；「全部」始终允许选择。选项必须显示当前组合下的结果数。
- 筛选区保持紧凑并使用站点统一的自定义滚动条，不出现浏览器默认滚动条样式。

### 3.3 结果与验收

- 文库 Hero 只保留主标题与当前数量／内容总数，不显示重复的「02／文库」装饰页签；移动端不得为已删除的页签保留空行或额外间距。
- 文库 Hero、筛选框架与内容索引的分隔线均与页眉同宽；不得在外层内边距范围绘制横线。
- 结果区沿用可见名称「文库」，其功能语义是内容索引；不额外显示「内容索引」标题。界面中不出现中英双语列名或单独的「打开」列。
- 移动端 Hero 将当前数量／内容总数与「文库」排在同一行；当前数量使用次于标题的字号层级，且两者在窄屏不得换行或互相遮挡。
- 条目按内容层既定顺序展示，普通内容进入 `/posts/<slug>` 或 `/media/<slug>`；每本书只生成一个进入 `/books/<slug>` 的连载条目。
- 文章署名和书籍署名中的姓名链接到 `/library?contributor=<id>`，默认展示该人在全部署名位置的内容；角色细分由文库中的「署名位置」面板完成。姓名链接默认不得自行附加 `role`。
- 首页与文库使用同一聚合口径：普通文章与每本书各占一个条目，书内章节不再额外展开为文库顶层条目。同一本书的章节仍继承书籍记录的全站号，并从书籍目录进入。
- 首页推荐卡页眉展示正确的栏目和主题；文库筛选面板生成的任一正常组合 URL 在分享后，活动项、计数和结果保持一致。
- 自动检查应覆盖全部真实栏目、主题分类、标签、贡献者和署名位置，确认正常界面生成的任一链接均至少得到一条结果。

## 4. 正文阅读页（案卷方案）

### 4.1 通用布局

- 正文页采用案卷式阅读界面，桌面与移动端按各自信息密度设计，不只是等比例缩小。
- 文章档案只保留实际存在的署名信息；原文题名、原刊和日期缺失时整行不渲染，不显示占位文案或资料声明。
- 桌面封面不设置带红色竖线的右侧「本文提要／原文资料」副栏；摘要、署名及原文信息不得在同一封面重复渲染。
- 当前滚动子标题与导航左侧主标题使用一致的字号、字体和垂直对齐。
- 目录使用站点自定义滚动条；注释和文献面板保留独立滚动，但隐藏可见滚动条以释放横向空间。侧栏或弹层不得与页脚重叠，滚到文章底部时仍可完整访问。
- 署名按作者、译者、校对顺序展开为独立贡献者记录。角色方块不在链接内；姓名链接到 `/library?contributor=<id>`。JSON-LD 中作者、译者使用原生属性，校对以 `contributor` 暴露，并都使用同一稳定筛选 URL。
- 正文封面的栏目文字链接到 `/library?section=<section>`，栏目内编号保持非链接；每个 `#标签` 分别链接到 `/library?tag=<编码后的标签>`。这些入口只建立被点击的单项筛选，不隐式叠加文章的其他栏目、主题或标签条件，也不再使用旧 `/search` 路径。
- 窄桌面端与移动端的文章目录抽屉只保留阅读进度、视觉行跳转、文章目录和返回篇首，不得重复页眉已经提供的「专题／连载／文库／关于」全站导航。
- 桌面封面不以视口高度制造大块空白；左侧栏目号、文章档案和进入正文后的阅读栏与页眉版心左缘统一对齐，标题档案结束后以紧凑留白进入正文。
- 桌面正文封面左栏的栏目字置于文章编号左侧，并与编号的可见字面底边对齐；编号组下方不绘制额外横线。栏目字使用 900 字重的微软雅黑，并以 Noto Sans CJK SC 作为后备，不使用等线或人工描边。左栏与标题区之间的竖向分隔线从封面顶部连续延伸至最下方标签行底部。该规则适用于全部博客正文。
- 桌面左侧阅读栏按「您正在读 → 署名 → 阅读进度 → 目录」排列，不再单列与目录重复的「当前章节」模块。「您正在读」使用黑色；进入黏性阅读状态后，其可见字面顶边、右栏「注释／文献」标题和版心第一条完整文字行必须处于同一水平线，并在页眉底线下保留明确的实色安全区。正文主滚动不在滚轮停止后执行二次平滑校正或“回正”，安全区负责遮住页眉下方的残行。省略泛称“署名”的可见标题；左栏保留方框式「作／译／校」角色 cmark，姓名仍链接文库。前三个模块之间只使用紧凑留白，不绘制红色或黑色横向分隔线。目录标题应与目录条目或空态说明组成同一视觉组，不得贴靠上方阅读进度。
- 移动封面不重复设置「本文信息」折叠栏。全站文章编号、发布日期和预计阅读时长与「返回首页」处于同一行，顺序为「返回首页 → 第 n 号 → 日期 → 时长」；档案号／栏目与返回行之间不设横贯分隔线，并以紧凑留白衔接。桌面封面与正文之间、正文完与相关推荐之间同样不使用横贯版心或视口的分隔线。
- 桌面、平板与移动端均将封面标签和连续正文视为相邻内容；两者之间只保留紧凑的区段留白，相较旧基线稳定回收约两行正文高度，封面最小高度不得抵消这一收紧量。
- 桌面封面删除左栏底部重复的「屋顶现视研／文章／第 n 号」信息块；全站文章编号只在标题上方的返回／日期／时长行出现。连续正文从完整封面之后开始，不以负外边距覆盖尚未结束的左栏。
- 桌面封面标题区在原右侧提要删除后横跨正文列和右栏直至版心右缘，不再保留旧 740px 限宽或自动均衡换行。front matter 使用 `title_breaks` 提供优先断点：一行可容纳时不强制换行；需要换行时避免第二行以「的／之」等非实词开头、避免切进实词内部，并避免相邻两行长度悬殊。字段缺失时内容校验必须给出建议和警告。封面高度必须由实际内容决定；标题从两行变为一行时同步收回一行高度，不保留预留空白。
- 桌面正文页眉与主页共享同一 1280px 版心契约：品牌锁组对齐版心左缘，专题、连载、文库、关于四项紧随品牌靠左排列，底部分隔线与阅读进度只横跨版心而不贯穿视口。移动端保留章节按钮与阅读工具的专用重排，底线对齐其 16px 内容边距。
- 宽桌面的正文列始终以视口中心为绝对中轴，左右阅读栏采用对称栏宽；三栏总宽不得越过页眉版心的左右边缘，注释与文献不得越出版心右缘。
- 正文内的章节标题不绘制贯穿正文列的实心黑色上边线，并使用紧凑的标题前间距。表格不使用逐格黑框、单元格底色、表头底色或等宽正文，只保留柔和横向分隔、清晰表头字重和适合连续阅读的字体。
- 正文页相关推荐不显示装饰编号，展示三张候选卡；整卡在鼠标悬浮或键盘聚焦时沿用首页卡片的反色选中反馈。

### 4.2 视觉行进度

- 进度以浏览器实际排版后的**视觉行**为单位，而不是 Markdown 源文件行号。
- 当桌面三栏保留且 CSS 视口达到 `1200px` 时，正文左右两侧每隔 10 个视觉行显示一个低对比度行号；这也覆盖 1080p 屏幕在 150% 系统缩放下约 `1280px` 的 CSS 视口。标号来自同一套字体加载后视觉行测量，字号或字族变化后同步重算；更窄桌面和移动端隐藏。
- 界面同时显示当前行、总行数和进度条；「阅读进度」使用黑色，字号与「目录／注释／文献」标题一致，右侧当前行数字与「阅读进度」同字号，总行数以较小灰字作为辅助信息。行数不使用千分位符号。点击当前行数后，同一位置切换为数字输入框，按 Enter 跳转；点击输入框以外任一位置即退出输入并恢复当前行数。输入框不绘制下边线，文本选区使用当前明暗主题的反色令牌，不得暴露浏览器默认蓝色。非法值不可提交，越界值应被拒绝或限制到合法范围，不另设常驻的跳转输入栏或提交箭头。
- 当桌面左栏正在显示阅读进度时，页眉只保留版心底线，不重复绘制红色阅读进度条；左栏被收起的断点和阅读方向仍可在页眉显示进度。
- 字体完成加载、容器尺寸变化、图片加载和正文布局变化后必须重新测量；测量中状态应稳定，不得把临时计算样式固化为最终过大字距。
- 跳转后目标视觉行应避开固定导航，并尊重 `prefers-reduced-motion`。
- 普通文章与书籍章节页默认启用完全本地的阅读记录；记录只写入当前浏览器配置文件在本站域名下的本地存储，不上传服务器、不使用 Cookie，也不跨浏览器、浏览器配置文件或设备共享。存储不可用、被清除或被浏览器回收时，正文仍须正常阅读。
- 持久位置以正文语义块指纹、相邻块、章节锚点和块内位置为主，视觉行及全文比例只作为当前排版下的精确定位和降级信息。每次构建生成 `contentRevision` 内容版本标识；修订版本变化后优先匹配仍存在的原语义位置，不能把旧的绝对 `scrollY` 或旧百分比当作唯一锚点。
- 读者直接以不带 hash 的文章 URL 重新进入时，页面在字体、图片和首次视觉行测量稳定后自动恢复，不显示或提供「继续阅读」入口。显式章节、脚注、文献及 `#reading-cover` 等 hash 始终优先；浏览器前进后退、刷新、BFCache 或其他原生滚动恢复也优先，客户端不得执行第二次跳转。自动恢复完成前若读者已经主动滚动或触摸页面，应取消恢复。
- 已读完的文章追加同页内容后，仍自动恢复到旧版本的原完成位置，不自动跳过旧位置或直接进入新增内容；读者自行决定是否继续向后阅读，越过新版正文结束位置后才把新版标记为已读完。原位置发生编辑时按语义块、相邻块、章节和全文比例依次降级，并在只能近似恢复时避免宣称精确定位。
- 阅读设置提供「保存本机阅读记录」开关（默认开启）、「清除本文记录」和「清除全部阅读记录」。关闭开关后停止保存与自动恢复，但不得影响主题、字族和字号等其他本地设置；清除操作只作用于明确选择的阅读记录范围。

### 4.3 目录

- 目录位于左侧文章档案下方；一级结构常见可见，二级及更深标题必须能够逐支折叠和展开。
- 目录未选中项使用主题的柔和灰色，当前标题与右侧栏选中条目的正文一样使用黑色或主题的 `--ink`；当前项和已展开状态必须同时由字重、标记或尺寸等非颜色线索识别。
- 一级目录编号左缘与「目录」标题左缘对齐；目录标题允许自然换行，续行与标题首字对齐，不使用首行缩进、悬挂缩进或省略号截断。
- 当前标题所在的父级链逐级展开；切换到另一父级分支时，自动收拢上一分支并展开新分支。该规则递归适用于三级、四级及更深层级。
- 目录父子分支展开与收拢使用短促、平滑的高度和透明度过渡，并尊重 `prefers-reduced-motion`；编号列、层级缩进与标题列只保留紧凑间距，缩进收窄后必须把腾出的宽度交还标题，不得维持旧的提前换行点。
- 点击目录项跳转到对应正文标题，并使该标题避开固定导航。
- 宽桌面文章含有正文图片时，在「目录」右侧提供「图录」切换；「目录」原有位置、字体和字号保持不变。两者下方只使用一条与两个汉字等宽、与左栏阅读进度条同厚的红色短线指示当前面板，红线随面板横向滑动，不绘制灰色底轨或半透明选中底色。
- 书籍章节页在「目录／图录」右侧始终增加「全书目录」。已发布的其他章节可跨页跳转，待更新章节可见但不可点击；当前章节回到篇首，并在其下嵌入本章标题目录供章内跳转。全书目录复用普通目录的窄编号列和紧凑列间距，编号列最小宽度为 `16px`，只为「前 1／附 1」等不可拆分的复合编号按内容扩展；章名不得因独立展开按钮而远离编号，次级标题的灰色 `↳` 与编号列左缘对齐。三种索引在桌面侧栏与窄屏目录面板中保持同一信息和行为。
- 阅读进度与目录／图录切换必须保持不同的状态层级：阅读进度表达连续比例，需要灰色全长轨条作为对比刻线；目录／图录只表达两个离散面板，若也加入灰色轨条，会与上方阅读进度混淆，因此切换器的红线优先直接贴近文字。
- 图录按正文顺序显示「图1、图2……」；存在图注时，仅当对应图片处于版心可见范围内才展开图注并呈现选中状态。点击图录项后，图片上界对齐正文版心顶部；支持 `scrollend` 的浏览器在平滑滚动真正结束后校正像素，不支持时以连续稳定帧判断结束，不得使用固定截止时间中断长距离滚动。

### 4.4 注释与文献

- 宽桌面右侧仅渲染文章实际具有的注释或文献；每个面板最多占可用侧栏高度的一半，两者都有时上下分区并独立滚动，只有一类时仍只占半高，两者都没有时整栏不显示。两个面板之间不绘制实心黑色分隔线。未选中条目使用主题的柔和灰色，选中条目以红色标签和黑色或 `--ink` 正文明确区分。
- 注释与文献列表的相邻条目之间不绘制灰色或其他横向分隔线，层级依靠编号、留白和选中状态表达。
- 注释／文献编号与条目正文之间只保留紧凑空隙；编号列随标签实际宽度扩展，长罗马数字不得与正文重叠。正文同一位置同时出现文献注和内容注时，两类上标之间插入一个可见空隙。
- 选中条目的编号与详情第一行处于同一行并顶端对齐，不得把详情另起到编号下方。面板标题右侧显示「当前条目 / 总条目」：当前条目使用黑色且与标题同高，斜线和总数使用更小的灰色文字。点击当前条目数字后原位输入具体序号，按 Enter 跳转，点击外部退出；输入选区与阅读进度使用相同的主题反色样式。
- 在桌面侧栏或移动端弹层内直接点开折叠条目时，列表滚动容器保持点击前的 `scrollTop`（允许 1px 渲染误差），详情从该条目位置以平滑高度和透明度过渡自然向下展开，不自动把详情底部滚入视口。由正文引用或跨引用定位侧栏条目时使用平滑滚动，并尊重 `prefers-reduced-motion`。用户停止滚动后，可在一个文本行以内轻量校正被顶部边界裁切的行，不得跳过完整条目或妨碍条目自然展开。
- 两个引用面板不显示滚动条，条目采用紧凑垂直间距；标题与内容、内容与底部操作区之间均不绘制灰色分隔线。底部操作依次为「首条注释／文献」「末条注释／文献」「原文位置」：三个按钮使用低对比度同色实心底、无描边，悬浮或键盘聚焦时才切换为主题反色，以降低常驻视觉权重；前两项只把当前面板平滑滚到顶部或底部，后一项把正文与视觉行进度定位到当前选中引用在原文中的角标位置。左栏「返回篇首」不显示箭头或上分隔线，沿用同一按钮样式，并把窗口真正滚动到页面顶部。左右栏按钮底边使用同一安全边距，并尽量与版心最后一条完整文字行底边对齐，不得完全贴住视口底部。
- 移动端文末完整渲染注释和文献。由注释中的文献引用进入文献时，应在同一个弹层内切换内容，并提供清楚的返回路径；不得先关闭弹层再在页面下方滚动到另一组内容。
- 注释或文献中的表格按实际列数进入侧栏：两列表格保留完整侧栏预览，并为末列数字预留不可拆分的自然宽度；三列及以上表格不得压缩复制到侧栏，改为「查看文后表格」链接，跳转时自动展开对应的文末注释或文献并定位原表。文末原表始终完整保留。
- 文末注释和文献组上下及彼此之间不绘制实心黑色分隔线，内容层级由标题、计数和留白表达。
- 文末注释和文献正文只比当前正文小一个字号，并随阅读字号设置同步变化。
- 返回操作需要保留跨引用历史；关闭后恢复到触发脚注、文献引用或工具按钮。

### 4.5 断点与入口

- `>=1360px`：使用完整桌面案卷。左侧为署名、视觉行与目录；右侧按文章实际具有的引用类型显示注释、文献或双区。
- `768–1359px`：可以收起左右侧栏，但工具区必须提供明确的「目录」入口；打开后仍可访问当前行/总行数、行号输入跳转和完整可折叠目录。仍保留三栏且视口达到 `1200px` 时，按 4.2 显示正文双侧视觉行号。不得出现功能真空区。
- `<=767px`：移动工具栏只提供目录与阅读设置，不设置独立的「注释／文献」按钮；注释和文献通过正文引用角标、条目间引用及文末完整列表访问。底部弹层保持触控命中区和安全区域。阅读习惯面板以右侧抽屉水平平移进出并覆盖页眉，面板标题行与页眉使用同一顶边和高度；页眉中的主题、繁简与阅读习惯三键在整个过程中保持原有顺序、位置和 DOM 节点，不迁入面板。面板标题行提供独立关闭按钮，关闭后焦点恢复到页眉的阅读习惯按钮。桌面与平板沿用同一稳定页眉和抽屉动画合同。
- 封面与桌面阅读栏的紧凑化不重组 `<=1023px` 的独立封面和目录抽屉；行数跳转、完整目录与触控命中区必须保持可用。

### 4.6 字体与移动排版

- 阅读设置只显示「衬线」「无衬线」和字号等读者可理解的选项，不展示具体字体方案清单。
- 衬线正文：中文正文与标题使用本站自托管 Noto Serif SC，西文/数字以 Times New Roman 链为首选；中文引文、题记、署名和编辑按使用本站自托管 `Roof WenKai`，西文引文使用 Garamond 链。CJK 引号和间隔号必须由合适的中文字体承载，不得被西文字体带走。
- 无衬线正文：中文正文、引文和界面使用本站自托管 Noto Sans SC，西文/数字使用 Helvetica Neue 等西文无衬线链。中文强调仍以 `Roof WenKai` 的直立字形与正文区分，不得退化为粗体或合成斜体；其中西文按无衬线 italic 显示。
- 标题在两种正文主题下均使用 Noto Serif SC；目录、注释、文献和设置等 UI 使用 Noto Sans SC。Reader 主标题中的方向性左右引号与左右书名号保留完整全角字形，只回收开标点左侧和闭标点右侧约半字的外侧留白；不得用缩放、裁切或原子内联盒压扁字形、破坏中文标点禁则。切换主题时西文、数字和标点必须一起切换；背景不得出现模糊竖线。
- 所有方框式 `cmark`（包括左侧阅读栏的「作／译」）统一使用加粗 Noto Sans SC 字形，确保两种角色标记的字形和字重一致。
- 正文内以 `.signature-block` 标记的署名行使用本站自托管 `Roof WenKai`，字号始终与当前正文设置一致。
- 首页及常规页面页眉的主题切换按钮与正文阅读页使用同一紧凑按钮样式和「☼／☾」符号，不另设描边方框方案。
- `<=767px` 的正文使用 `text-align: start` 与 `letter-spacing: 0`，依靠浏览器原生中文断行，不强制两端齐行。版心左右内边距固定为**左 24px、右 16px**（逻辑方向环境下保持同等视觉意图）。
- 旧研究文档中关于强制 `justify`、实验性 em 字距和自定义整段断行的内容仅供研究，不构成现行标准。

### 4.7 正文验收

- 至少在 375px、768px、1024px、1280px、1360px 和宽桌面检查目录、行号、注释、文献与页脚。
- 在 1600px 桌面侧栏及 390px 移动弹层分别检查注释、文献的直接展开：`aria-expanded` 变为 `true`，详情平滑向下自然展开，且点击前后滚动容器的 `scrollTop` 变化不超过 1px；另行确认正文引用与跨引用能平滑把目标条目按钮带入可见区，首条／末条操作定位面板边缘，原文位置操作定位当前引用角标。
- 使用 Firefox 与 Safari/WebKit 检查移动断行；最终样式必须保持起始对齐和零额外字距，不以两浏览器恰好在同一字符换行作为验收条件。
- 正文 `h1 / h2 / h3` 共用从 `01` 开始递增的红色小数字标题标记；`h3` 保留较小字号表达层级，但不得退回破折号。桌面两端对齐正文必须禁止在行内脚注与后续正文之间断行，不能把脚注前的短行扩张到异常字距；发布前以公开 sitemap 中全部普通正文和书籍章节页为扫描范围。
- 用键盘检查工具按钮、目录树、跨注释/文献引用、弹层焦点循环、`Escape` 和焦点恢复。

## 5. 多媒体详情页与内容模型

- 独立多媒体条目拥有 `/media/<slug>` 站内详情页，只展示标题、简介、封面/静态资料、站外平台链接和关联站内文稿。
- 站外链接可以指向 YouTube、哔哩哔哩、Apple Podcast 等平台；必须清楚标示平台并安全地在新窗口打开。
- 页面产物不得包含第三方 `<iframe>`、任意手写原生 `<video>` / `<audio>`、`<object>` 或 `<embed>`。文章正文仅可通过仓库规定的 `[video]` 与 `[audio]` 语义标记播放 `assets.labonroof.top/wechat-video/` 下已登记的 MP4 或 `assets.labonroof.top/wechat-audio/` 下已登记的 MP3；两者均禁止自动播放并保留原生控制条作无脚本后备。视频源有多个真实画质时，站内选择器在切换文件后保留时间点与播放状态；播客界面提供进度、前后15秒和倍速。净化器拒绝其他主机、路径、手写播放器及伪造的清晰度集合。
- `related_posts` 是仅允许 `section: multimedia` 使用的 front matter 列表。每个值必须是已存在、已发布且非多媒体的显式文章 slug，不得重复或指向自身；详情页按声明顺序展示零篇或多篇关联文稿。
- 首页推荐墙每次完整载入时，从「论／评／译／访／社」各随机抽取一篇，再从其余文稿中随机补足十篇；同一次页面停留期间不自行换稿。静态 HTML 与无 JavaScript 环境使用同样覆盖各栏目的稳定后备结果。下方「最新更新」始终维持日期排序，不参与随机。
- `featured_order` 仅作为旧内容兼容字段保留；随机推荐墙不读取它，不得用它暗中改变抽取概率。
- 旧 `/posts/<multimedia-slug>` 必须永久重定向到对应 `/media/<slug>`。

## 6. 书籍与连载

- `/books` 是书目索引；`/books/<slug>` 是一本书的状态、说明、递归目录、章节入口和阅读选择页。书籍清单位于 `source/_books/*.json`，与仅在构建期使用的 `book_document: true` Markdown 源分离。目录节点可以通过 `children` 继续嵌套，公开顺序严格遵循父子数组的书写顺序。
- `/books` 的书目顺序固定为「连载中（`serializing`）→ 暂停更新（`paused`）→ 已完结（`complete`）」；同一状态内按 `updatedAt` 从新到旧排列，再以书名稳定排序。任何连载中书籍都必须排在所有已完结书目之前，不能由较新的完结日期覆盖这一优先级。
- 每个新目录节点显式使用 `status: published / forthcoming`；旧平铺清单缺省状态仅作为兼容路径按 `published` 读取。两种状态都在书籍详情目录中可见；`published` 显示真实阅读入口，`forthcoming` 明确显示待更新状态且不可点击。聚合页和详情页的章节统计均按递归目录显示已发布数量／全部数量。
- 每个 `published` 节点生成真正的 `/books/<slug>/chapters/<chapter-id>` 独立正文页，并作为自身 canonical 进入 sitemap；`forthcoming` 不生成章节路由。构建期按清单 anchor 从书籍 Markdown 源切出本章，只渲染本章正文及其实际引用的注释／文献，禁止把整本书 HTML 注入任一章节页。
- 共享同一个章节标题的连续分篇不得建成目录 `children` 或独立章节页；父章保留唯一 canonical，分篇计划记录在父节点的 `sections` 中，已发布分篇以该正文页内带稳定 id 的 `h3` 副标题连续排布，待更新分篇只保留不可点击的目录状态。文章目录与全书目录对已发布分篇执行页内或跨页 hash 跳转。真正只承担结构分组、没有正文的节点才使用 `presentation: navigation`。
- 书籍页始终提供「从第一章阅读」「阅读最新章节」两个明确入口，分别指向首个已发布章节和 `latestChapterId`。章节页顶部入口只写「返回目录」，不重复书名；整本书作为一个公开条目参与全站与翻译栏顺序，所有章节页（包括 `reading / reference / navigation`）共同显示这本书的「译 NN」和「第 NN 号」。元信息与「连载 + 书名：副题 + 中文章节序数」眉题共用普通正文的封面元信息分组：组内间距紧凑，组后再与主标题拉开；其中「连载」使用灰色弱化文字，书名与副题以全角冒号合并为一个普通字重、黑色正文文字的连载目录链接，中文章节序数使用红色强调文字，与专题眉题的「灰色类型 → 黑色名称 → 红色编号」层级一致。主标题、简介、署名和标签沿用普通正文的垂直节奏。封面和正文之间不绘制灰线。
- 章节页的上一章／返回目录／下一章导航使用统一的两层按钮结构与表面样式，导航上方不绘制黑线；阅读位置按章节 URL 独立保存。书籍 Markdown 源不生成 `/posts/<documentSlug>` 公开页面、canonical、RSS 或 sitemap 项，也不为旧全文 URL 提供兼容跳转。
- `latestChapterId` 必须指向递归目录中现有且状态为 `published` 的节点；节点 id、number 以及已发布节点的 anchor 在整棵目录树内唯一。`forthcoming` 节点必须省略 `anchor / publishedAt`，且不得包含状态为 `published` 的后代；待更新节点不参与锚点存在性校验。书籍 `updatedAt` 与承载正文的 `updated/date` 同步更新。
- 每个章节节点可选填独立 `tags`；未填写时继承整本书 Markdown 的标签。章节页必须渲染最终标签集合，并链接到相应文库标签筛选。
- Book JSON-LD 的 `hasPart` 只列出递归目录中的 `published` 节点，并保持公开目录顺序；待更新节点不进入结构化数据。Chapter URL 必须为绝对 URL，章节 `position` 在已发布节点序列中从 1 开始；Book 同时包含 publisher、发布日期和修订日期。书籍页作者／译者／校对姓名使用贡献者稳定 id 链接文库。
- 后续更新继续向同一个 `documentSlug` 对应的 `book_document: true` Markdown 构建源追加内容，再把既有待更新节点切换为 `published` 并补齐 `anchor / publishedAt`。运行时页面按章节隔离，编辑源仍可保持单文件，以免机械拆分或搬运超长译文造成内容差异。
- 书籍清单使用 Zotero 结构化 `citations.original / citations.translation`，构建期生成 BibTeX。原书与译本是两个独立复制位：有对应记录才显示紧凑的复制控件，并提供成功／失败反馈；缺失资料不得用另一版本或虚构记录代替。译本必须作为 `book`，引用 URL 固定为 `/books/<slug>`。
- 每个公开正文页均提供本页 BibTeX 一键复制和 `.bib` 下载；Zotero Embedded Metadata 同时暴露精确 `itemType`。普通正文缺省为 `blogPost`，已核验的译载资料可使用 `bookSection / journalArticle / preprint / thesis / interview`。
- PDF 与 EPUB 下载彼此可选，只在对应 URL 实际存在时显示真实下载链接；不得渲染禁用按钮、空链接或占位地址。站内文件使用根相对 URL，站外文件只接受 HTTP(S)。
- `/books` 与 `/books/<slug>` 应以清楚而紧凑的书目层级、连载状态和阅读路径为主；聚合页首屏应尽快露出首条书目，详情首屏应尽快进入两个阅读入口，不用超大留白或装饰遮挡书名、署名、章节与资源操作。聚合页主体与页脚之间不得使用横贯视口的分隔线，书目内部的版心分隔线保留。连载聚合页、书籍详情及页尾交界的内容与横线均与页眉同宽，不得跨出版心。

## 7. 专题

- 专题聚合页与专题详情的内容、面包屑和分隔线均与页眉同宽；不得以外层内边距之外的宽度绘制横线。

- `/topics` 展示编辑部人工策展的主题集合；`/topics/<slug>` 展示导语、「从这里开始」和有序内容分组。专题不是标签搜索结果，也不由算法自动生成。
- 专题源位于 `source/_topics/*.md`。它包含 `title / subtitle / summary / status / published / updated`、可选 `curators`、正文导语和 `groups`；数组顺序就是公开编排顺序。分组可显式填写专题内唯一的两位 `number`，序言单元允许使用 `00`；未填写时按数组顺序生成 `01 / 02 / …`。
- 条目引用类型只能是 `post / media / book`，以稳定 slug 指向已发布实体，并可附 `editorialNote`。首组首项是「从这里开始」入口；重复、缺失、草稿或类型错配引用必须阻止发布。
- 专题详情使用 CollectionPage JSON-LD，并按编辑顺序输出绝对的 `hasPart` URL。专题索引与详情均进入 sitemap；专题不作为 RSS 内容条目重复发布。
- 专题索引与详情的视觉层级必须紧凑地区分专题状态／摘要、导语、分组和条目；索引首屏应露出首条专题记录，详情从浅色标题区直接进入导语。首组首项以内联「从这里开始」标识呈现，不得在页面中重复渲染同一条目。装饰不得穿过标题或编者按，也不得削弱人工阅读顺序。

## 8. 关于页与联系入口

- `/about` 只保留联系入口，以「联系我们」为主标题；投稿、勘误与一般事项统一使用 `a1835631041@163.com`，站外主页在同一区域列出。
- 发表过文章或翻译不等于编辑部成员。贡献者资料不从一次署名自动推断为团队身份。
- About 使用独立 canonical 与 OpenGraph，不使用首页的通用分享标题；其页脚沿用全站居中的品牌组，并作为唯一显示「最新修改」构建时间的位置，不再设置单独的左对齐署名或重复联系信息。

## 9. 搜索发现与订阅

- 所有可索引页面必须输出与自身一致的 canonical；文章、多媒体、书籍与专题详情输出匹配实体的 OpenGraph 和 JSON-LD。OpenGraph 的 `og:site_name` 统一为「屋顶现视研」，暂不输出 `og:image` 与 `og:locale`；不单独维护平台专用标题、摘要或图片，框架生成的兼容分享标签共享同页 OpenGraph 的标题与摘要。结构化数据中的站内 URL 使用绝对地址。
- sitemap 包含首页、专题／文库／书籍／关于聚合页、专题详情、书籍详情、已发布书籍章节以及所有文章和多媒体 canonical；不包含 `/search`、书籍 Markdown 构建源或带筛选查询参数的文库 URL。
- 聚合页 `lastmod` 取对应内容源的最近真实更新时间，不使用构建时间。About 没有可靠内容日期时省略 `lastmod`。
- RSS 保持“已发布文章与多媒体正文”这一内容流；书籍构建源、书籍落地页、章节页和专题策展页均不进入 feed。RSS 内部资源 URL 必须绝对化。
- 文章、书籍或专题源变更推送 `main` 后，IndexNow 同时提交实体 URL 和相应聚合页；Google 继续依靠 sitemap。

## 10. 自动门禁与变更规则

- `npm run validate:content` 校验贡献者登记与署名、文章 front matter、书籍／章节清单、专题编排、跨实体引用、日期一致性和唯一性。
- `npm run validate:media-html` 以恶意样本校验多媒体 HTML 允许列表、主动内容和危险属性过滤。
- `npm run typecheck`、`npm run lint`、`npm run build` 必须非交互执行并以非零状态阻止合并。
- `npm run verify:release -- <base-url>` 对已经启动或线上站点执行导航、文库筛选、贡献者链接、正文、多媒体、书籍、专题、About、重定向、canonical、OpenGraph、JSON-LD、sitemap 和 RSS 的 SSR／HTTP 回归；它不执行客户端 JavaScript 或真实浏览器交互。`verify:editorial` 保留为兼容别名。
- `npm run check` 是本地确定性静态与纯逻辑门禁；GitHub Actions 按现行去重策略在 `main` 分支 push 和所有 pull request 上运行锁定依赖安装、完整 `check`、生产构建和本地 `verify:release`，不为功能分支 push 重复执行同一套门禁。浏览器断言、项目矩阵、UCCTB 执行边界和 `planned / implemented / gated / baseline-verified / manual / not-covered` 状态以 [`testing.md`](testing.md) 为准；资产存在不能被描述为某个分支或生产环境最近一次已经通过。
- 任何改变本文规范的产品决策，应在同一变更中更新本文、相关交付文档和对应自动断言。
